# MD Sound Module PCM/DAC Phase Note

This note records the first minimal PCM/DAC phase after the FM and PSG success
baseline. The goal was to verify the VGM DAC stream path without disturbing the
existing FM/PSG playback state.

## Scope

Implemented only the minimal uncompressed YM2612 DAC stream flow needed by the
current target VGM test.

Supported in `vgm_inspector --emit-sv`:

- VGM `0x67` data block with type `0x00`
  - Treated as an uncompressed PCM bank.
  - Emitted into the testbench include as `pcm_bank[]`.
- VGM `0xE0`
  - Treated as PCM seek.
  - The following 32-bit little-endian value sets `pcm_pos`.
- VGM `0x80`-`0x8f`
  - Treated as DAC stream / wait commands.
  - Reads one byte from `pcm_bank[pcm_pos]`.
  - Increments `pcm_pos`.
  - Generates a YM2612 DAC data write:

```systemverilog
send_ym(1'b0, 8'h2A, pcm_bank[pcm_pos]);
```

- YM register `0x2A`
  - Generated by the DAC stream path above.
- YM register `0x2B`
  - DAC enable writes are still handled by the existing normal YM write path.

Verbose per-command output is guarded by `VERBOSE_TB_LOG`, so the normal test
run remains summary-only.

## Not Yet Supported

- VGM `0x90`-`0x95` DAC Stream Control commands.
- Compressed VGM data blocks.
- Multiple PCM banks.
- Full VGM long playback with PCM from the beginning of the song.
- Complete loop handling.

## Conclusion

The minimal uncompressed PCM/DAC stream path is now confirmed for a short 5k
simulation window. The test generated YM2612 register `0x2A` DAC writes from
VGM `0x80`-`0x8f` stream commands, kept DAC enable on the existing `0x2B` YM
write path, and preserved the edge-synchronized wait/WAV accounting.
